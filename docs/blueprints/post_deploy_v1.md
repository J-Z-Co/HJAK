## 2. 重复部署

这一节是操作手册。网站能打开，靠的是容器接到请求，不是把 `public/` 当成静态站。

### 2.1 怎样算成功

```bash
curl -sI https://hjak.vercel.app/up
curl -sI https://hjak.vercel.app/
```

成功时两条都没有 `content-disposition` 里的 `filename="404.html"`。`/up` 是 `HTTP/2 200`。`/` 在未登录时进入登录页。

若响应头仍是 `filename="404.html"`、`server: Vercel`、`x-vercel-cache: HIT`，请求停在静态文件，Rails 没接到。这和数据库、邮件、Host 白名单无关。

### 2.2 仓库里已经有、并且必须留着的

| 文件 | 作用 |
|------|------|
| `Dockerfile.vercel` | 生产镜像。编译样式后监听 `PORT`，默认 80 |
| `bin/vercel-entrypoint` | 把 `POSTGRES_URL_NON_POOLING` 或 `POSTGRES_URL` 抄成 `DATABASE_URL`，执行 `rails db:prepare`，再启动 Puma |
| `vercel.json` | 声明容器服务 `web`，并把全部路径转给它 |
| `config/database.yml` 的 `DATABASE_URL` 分支 | 只有一份主库。不再要求 cache / queue / cable 三个库 |
| `config/environments/production.rb` | `assume_ssl` 打开；有 `DATABASE_URL` 时缓存用内存、任务用 async |
| `config/cable.yml`、`config/cache.yml` | 有 `DATABASE_URL` 时不再去连名为 cable、cache 的库 |
| `.dockerignore` | 构建时不把 `config/master.key` 打进镜像 |
| `config/credentials.yml.enc` | 在 git 里。密钥本身不在 git 里 |

本地开发仍用 `Dockerfile.dev` 和 `compose.yaml`。主进程仍是 `bin/dev`。发布用的镜像不替换这条路。

### 2.3 Vercel 项目要保持的设置

项目是 `hjak`，代码仓库是 `J-Z-Co/HJAK` 的 `main`。

| 设置 | 要保持的值 |
|------|------------|
| Framework Preset | **Container**。设成 Other 时，即使仓库里有 `Dockerfile.vercel`，也会只发布 `public/`，于是返回 `public/404.html` |
| Install Command、Build Command、Output Directory | 都空着。Output Directory 不要填 `public` |
| Postgres | 接到这个项目。启动脚本读取它注入的 `POSTGRES_URL_NON_POOLING` 或 `POSTGRES_URL` |
| `RAILS_MASTER_KEY` | 环境变量，值等于本机 `config/master.key` 的那一行。不写进仓库，不贴进聊天和构建日志 |
| `SOLID_QUEUE_IN_PUMA` | 不设置 |
| `PORT` | 不设置。容器默认 80，Puma 读取 `PORT` |
| `APP_HOST` | 现在可以不设。邮件链接会用 Vercel 提供的生产域名 |

Hobby 套餐可以跑这个容器。空闲大约 5 分钟后实例会停，下次打开要等它再启动并做一次 `db:prepare`。迁移已经做过时，这一步只是核对，不是重灌数据。单次最长约 300 秒，内存 2 GB。

### 2.4 每次改完代码之后

在项目目录执行。密钥文件不要放进 `git add`。

```bash
cd ~/PhoenixList
git status
git add 改过的文件
git commit -m "$(cat <<'EOF'
说明这次为什么改。

EOF
)"
git push origin main
```

推送后 Vercel 会构建镜像。构建日志里应出现镜像构建，耗时是分钟级。若日志写 `Detected framework: Other` 并且几十秒结束，回到 §2.3 把 Framework Preset 改回 Container，再重新部署。

有新的迁移文件时，不需要登录机器去跑。下一次容器启动时的 `db:prepare` 会把它补上。本地开发库另在容器里执行：

```bash
docker compose exec web bin/rails db:migrate
```

生产环境不要执行 `db:seed`。那会写入口令为 `seed-password` 的手测账号。

### 2.5 失败时先看响应头

| 看到的 | 含义 | 先做 |
|--------|------|------|
| `filename="404.html"` | 仍是静态站 | Framework Preset 改为 Container，清空 Output Directory，确认 `vercel.json` 已推送 |
| `502`，或部署失败 | 容器没能听端口，或启动脚本退出 | 看该次部署的构建日志和 Runtime Logs。常见原因是没有数据库地址，或 `RAILS_MASTER_KEY` 不对 |
| Rails 的报错页，没有 `filename="404.html"` | 请求已经进了 Rails | 按日志里的异常修，不再改静态站设置 |
| `/up` 为 200，首页是登录页 | 部署成功 | 按 §2.1 结束检查 |

### 3.1 Host 白名单是什么

浏览器访问 `https://hjak.vercel.app/` 时，请求里会带一行 `Host: hjak.vercel.app`。这就是地址栏里的域名。Rails 可以要求：这行必须在允许名单里，否则直接拒绝，页面是 403，文案大意是 Blocked host，进不了登录页。

这项检查挡的是「有人用另一个域名打开你的程序」。例如别人把 `evil.example` 指到同一台服务，用户以为自己在那个域名上，密码重置链接或缓存却可能被带到不该去的地方。名单里没有的域名会被拒绝。

现在生产配置里名单是空的。空名单的效果是不检查。所以今天用 `hjak.vercel.app` 能打开，是因为谁来都放行，不是因为已经把这个域名写进去了。

若改成只允许 `hjak.vercel.app`：

| 谁来访问 | 结果 |
|----------|------|
| 家里人打开 `https://hjak.vercel.app/` | 和现在一样 |
| 另一个域名指到这个部署 | 403，打不开 |
| Vercel 的预览域名，或以后买的自己的域名 | 同样 403，直到把那个域名加进名单，并在需要发邮件时设置 `APP_HOST` |
| 健康检查 `/up` | 单独排除，不查 Host |

`/up` 要排除，是因为探活请求的 Host 有时不是对外域名，而是平台内部地址。探活若得到 403，Vercel 可能把一次正常启动看成失败。用户打开的首页、登录页仍然检查。

不做的后果：网站继续能用。在你还没有第二个域名时，多出来的风险只是「理论上别人可以用陌生域名碰到这同一个程序」。这不是当前打不开页面的原因。

做错的后果：域名写错，或忘了排除 `/up`，首页或健康检查变成 403，看起来像网站挂了。2026-10-18 决定暂不做。这行配置保持为空。

## 4. 记住登录

### 4.1 现状

`User` 已经启用 Devise 的 `:rememberable`。用户表已有 `remember_created_at`。登录页没有「记住我」，也没有默认打开它。

因此现在只有浏览器这一次会话的 cookie。关掉标签、系统回收这个窗口，或者从主屏幕图标进入另一个没有这份 cookie 的窗口，就要重新输入密码。Vercel 把容器停掉不会清掉浏览器里的 cookie。会话存在 cookie 里，不在服务器内存里。

`:timeoutable` 没有启用。不存在「30 分钟无操作就退出」。不需要为了保持登录去加超时模块。

退出登录时，Devise 已配置为作废记住用的令牌。这一点保持。

### 4.2 已确认的方案

2026-10-18 确认，并已写入代码。家庭使用是同一部手机反复打开，不设成可取消的勾选。

| 决定 | 建议 |
|------|------|
| 登录成功 | 一律记住。登录表单放隐藏字段 `remember_me=1`，不加勾选框 |
| 注册成功 | 同样记住。否则刚注册完只活在这一次会话里 |
| 记住多久 | 1 年 |
| 使用期间 | 打开 `extend_remember_period`。每次带着这枚 cookie 访问，期限从当天再延 1 年 |
| 退出 | 继续作废令牌。退出后必须输入密码 |
| 新表、新 gem | 不需要 |
| 超时退出 | 不加 |

记住用的是 HttpOnly cookie，脚本读不到。生产环境因为 `assume_ssl`，这枚 cookie 会带 Secure，只在 HTTPS 上发送。不用 `localStorage` 存登录态。

同一浏览器里，普通标签和「添加到主屏幕」之后的独立窗口不一定共用 cookie。在图标里登录一次之后，由图标自己记住。这和产品蓝图 §13 里已经写的预期一致。

### 4.3 已经改的

1. `config/initializers/devise.rb`：`remember_for = 1.year`，`extend_remember_period = true`。退出时作废令牌的那一行保持。
2. 登录页加上隐藏的 `remember_me`。页面上看不到新的勾选框。
3. `Users::RegistrationsController`：注册成功后的登录同样记住。
4. `spec/requests/remember_login_spec.rb`：登录后去掉会话 cookie 仍能打开记录页；退出后 `remember_created_at` 清空并回到登录页；注册同样写下记住 cookie。

不改测量、指数、群组。不改本地 Docker。生产要等这次代码推上去之后才生效。

## 5. 改善建议

### 5.1 可行性

可行。范围是两层：一条建议，下面可以有若干条补充。补充下面不能再补充。

文字必须存在数据库里。只写在浏览器里的话，刷新就没了，换一台手机也看不到。所以模型和一次迁移是这一功能的本体，不是额外负担。

「合理 / 不对」不另建投票表，也不记录是谁点的。2026-10-18 确认：数字就是建议（以及补充）上的两个字段，每次成功点击加 1。防连点只做在当前这一页上。

### 5.2 计数

| 行为 | 结果 |
|------|------|
| 点「合理」或「不对」 | 服务器把对应字段加 1，页面上的数字跟着变 |
| 同一次打开里再点同一个按钮 | 按钮在第一次点击后停用，不再发第二次请求。按住或连点不会一直跳 |
| 刷新，或离开后再进入 | 按钮恢复可点。再点再加 1。这是接受的 |
| 点错 | 不能取消，也不能改投。另一个按钮是另一次加 1 |

不使用 `localStorage`。刷新后要能再点，所以「已经点过」不能存进浏览器。停用只活在当前页面的脚本里：一点击就禁用，数字更新后仍然保持禁用，直到整页重新加载。

这样做挡不住有人刷新后再点，也挡不住直接调用接口。它只是让同一次停留里不能零成本连点。不再为每个用户记一票。

补充用同一套字段和同一套停用。补充下面不能再补充。

### 5.3 数据

一张内容表。不另做补充表，也不做投票表。

`suggestions`：

| 列 | 含义 |
|----|------|
| `user_id` | 作者 |
| `parent_id` | 空表示建议。有值表示补充，并且那个父记录自己的 `parent_id` 必须为空 |
| `body` | 纯文本。页面输出时转义，不把输入当 HTML |
| `reasonable_count` | 「合理」。默认 0，只增不减 |
| `wrong_count` | 「不对」。默认 0，只增不减 |
| `created_at` | 排序用 |

长度上限 1000 字。空白不保存。建议按新的在前。补充按旧的在前。

谁能看：全体登录用户都能看、能写、能点计数。公开注册保持开放，知道网址的人注册后也能写。

作者可以删除自己的建议或补充。删掉一条建议时，它的补充一起删。不做编辑。改字就删掉重写。

### 5.4 界面

「我」页在「纠正误输入」上方加按钮「改善建议」，进入列表页。

列表上方是输入框和「提交」。提交成功后这条出现在列表顶部，输入框清空。

每条建议卡：

- 第一行是显示名和日期
- 正文初始最多两行。用样式裁切，再用脚本比较完整高度和两行高度
- 超出两行：只显示「展开」。点「展开」后显示全文，并出现尾行
- 没超出两行：直接显示尾行
- 尾行三个按钮：「补充」、`合理 N`、`不对 N`。点过的那个按钮在这次打开里保持停用，数字停在加 1 之后的值
- 展开之后，卡片上另有「收起」。收起后回到最多两行，尾行重新藏起（短内容没有收起，尾行一直在）
- 有补充时，卡片最底一条通栏按钮，文案「存在 n 条补充意见」。点开后列出补充卡，文案改为「点击隐藏补充意见」

补充卡：

- 同样最多两行，同样的展开、收起、合理、不对
- 没有「补充」按钮
- 没有再往下的补充列表

点建议卡的「补充」：在这张卡里展开一个输入框和「提交」。提交后这条补充记在该建议下，输入框关闭，通栏按钮的条数加 1。补充列表当时若是打开的，新内容出现在列表末尾。

文案只有中文。版式沿用现在的手机栏、卡片和按钮，不另做一套视觉。

### 5.6 这一节不做

- 补充下面再补充

- 邮件或推送通知
- 按群组把意见隔开

### 5.7 预估影响（落实时再核对）

- 必要性：文字和两个数字要在刷新后还在，所以放在同一张表。防连点只停用当前页的按钮，不增加表。
