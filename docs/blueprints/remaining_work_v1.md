## 3. 实施顺序

后一步依赖前一步的页面结构。推送放在最后，并且可以整段不做。

### 3.1 榜单与近一年图

依据 `group_boards_v1.md`。不新增表。

先给 `Indices::Board.assemble` 加上「只采用某日及以前的测量」。不加这一步，改善永远是 0，年图的每个点也是同一条线。

然后改 `Groups::Leaderboard`：现状、改善、达标、徽章。`?board=week` 打开现状。群组页加「近一年」，单独一页，用已有的 D3。非成员打不开，沿用现在的成员校验。

**测试**（请求规格和服务规格，不新加浏览器驱动）：

- 现状名次与现在的综合榜一致
- 改善使用周一 0 点之前的测量做起点；今天新记的数不会同时充当起点
- 只在一个时点算得出的指数不进入改善差
- 变差的人有名次，排在改善和持平之后
- 达标：过期不计、未记不计、超过 20 岁且已记过的身高计入；0 项也有名次
- 未满 6 岁出现在达标榜，不出现在现状和改善的名次里
- `?board=week` 不再按「有记录的天数」排序；`?board=badges` 仍是徽章榜，0 枚不给名次
- 近一年：52 个周点；某一周算不出则该成员该段无点，不写成 0
- 非成员打开群榜、近一年、成员指数，都被送回群组列表，正文里没有成员名和测量值
- 现有 `leaderboard_spec`、`ranking_spec`、群组请求规格随新规则改写，不另留一套旧「本周天数」例子

### 3.2 催催（不含推送）

依据 `group_nudge_v1.md` §1–§7。新表 `nudges`，唯一索引保证同一人、同一天、同一群只催到一次。迁移文件写出后由你在本地执行；生产靠下次部署的数据库准备。

按钮在群榜成员卡上，不放进群主的移除列表。整行链接改成「点名字进指数，点按钮不跳转」。

**测试：**

- 有过期测量的他人卡片出现「催催」；自己没有；七项都没记过的人没有；超过 20 岁且已记过的身高单独不算过期
- 甲催乙一次后多一个 😜；甲再点不增加，且数据库仍是一行
- 丙再催，乙的卡片是两个 😜，页面上没有 `+2`
- 把日期拨到第二天、乙尚未新保存测量时，图标仍在；甲可以再催，图标变成三个
- 乙在记录页成功保存一条新测量后，图标消失；只改旧记录时不消失
- 乙没有任何过期项之后，按钮没有
- 另一个群看不到这次催促；非成员不能催
- 连续天数火苗还在；名次不因催促改变
- 退出群组或删除账号后，相关催促行删除

系统推送不在这组测试里。这组做完时，点催促不会发通知。

### 3.3 加载中的回弹

依据 `client_cache_v1.md` §2。与缓存无关，可以和 3.1 并行。从一次跳转开始到新页面加载完，再次点击不发起新访问；失败时停在当前页并提示再试，不恢复上一页快照。

现有测试用的是不跑浏览器的请求规格，造不出「加载到一半又点一次」。做法：

- 把「加载中是否忽略下一次点击」写成可单独调用的一小段脚本，用一条不启动浏览器的测试覆盖它的判断
- 真机或电脑上的慢网络手测写进该步的验收，不把它算成已经自动测过

### 3.4 六小时缓存与核对

依据 `client_cache_v1.md`。在 3.1 和 3.2 的页面稳定之后做，避免缓存住即将作废的榜单 HTML。

只缓存指数、群组、群榜、成员指数。记录页、登录、注册、纠正、改善建议不缓存。样式和脚本继续用现有的一年缓存，实施时核对生产响应头。

服务工作线程这一步才登记，而且全站只此一个。主屏幕清单已经打开，不要再注册第二个。退出登录时删掉该用户的页面缓存。

显示缓存后向服务器核对指纹。相同返回 304。不同则用 Turbo Stream 只替换变了的榜单或成员卡，并重算 6 小时。保存测量、改资料、入群、退群、催促成功之后，丢掉该用户相关缓存。

**测试：**

- 指纹相同：核对接口 304，不返回整页
- 指纹不同：响应里是替换成员卡或榜的 Turbo Stream，不是整页跳转
- 非成员即使知道群组代号，核对接口也不返回该群内容（与第 2 节的成员校验同一条）
- 保存测量后，该用户的指数指纹变化
- 催促成功后，该群的榜指纹变化；另一个群的指纹不变
- 退出后再登录另一个账号，核对不会带回前一个账号的页面（服务端不按网址发给别人；客户端缓存在退出时删除。后者用第 3.3 那种脚本测试覆盖删除是否被调用）
- 生产样式地址的 `cache-control` 含一年。这条在部署后的手测里核对，请求规格只断言开发配置里已经写了一年的生产头

浏览器里「先画出旧页面再替换」无法用现在的请求规格完整演完。自动测试锁住指纹和替换片段；手测锁住「6 小时内再次进入不用盯着空白」。

### 3.5 推送（可整段不做）

依据 `group_nudge_v1.md` §8。只有 3.4 的那一个服务工作线程存在之后才做。苹果手机要先添加到主屏幕才收得到；Safari 普通标签收不到。

点「催催」的同一次请求发出通知，不用定时任务，也不用现有的进程内 Action Cable。

**测试（若做）：**

- 没有订阅时，催促成功但不调用推送
- 有订阅时，同一次请求发出一条通知，正文是催促而不是健康数值
- 订阅属于另一个用户或另一个群时不发送
- 用户拒绝或删掉主屏幕图标后，过期订阅被丢掉，不反复重试

不做邮件，不做未读红点。
