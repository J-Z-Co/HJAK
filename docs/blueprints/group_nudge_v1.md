# 蓝图：群组成员「催催」

> 这份文件讨论：组员有过期测量时，其他组员能否在成员卡片上催一次，并让全组看到对应个数的小图标。
> 状态是草案。表情、图标留存已在 2026-10-20 晚确认。落实顺序见 `remaining_work_v1.md`。系统推送仍不做。

```yaml
模块: group_nudge（催促 / 每日一次 / 卡片图标）
蓝图版本: 0.2
状态: 草案
创建日期: 2026-10-20
修订日期: 2026-10-20
关联:
  - docs/blueprints/health_tracker_v1.md（测量间隔）
  - docs/blueprints/ui_redesign_v1.md（群榜卡片、连续天数火苗）
  - docs/blueprints/group_boards_v1.md（「时效内」与达标榜用同一套间隔）
  - docs/blueprints/client_cache_v1.md（别人的催促要刷新后才出现在对方缓存里）
前置: 无。确认后新增一张催促表，由你本地执行迁移
```

---

## 1. 可行性

可以做。现有数据里没有「谁在哪一天催过谁」，所以需要新的一张表，不能从测量记录里推出来。

不做推送、不做短信、不用后台定时任务。催促只出现在群榜那一列成员卡片上。对方下次打开或点刷新时才能看见。若个人页面缓存那份蓝图一并做了，未刷新的手机会晚一些才看到新图标，这是缓存时效内的预期结果。

群里有未成年人。按钮和图表使用「催催」和开玩笑的表情，不写贬低的句子。

---

## 2. 什么时候出现按钮

按钮加在群榜每一行成员卡片上，也就是现在点进去能看指数的那一行。不放在页底只有群主能看到的「移除」列表里。那一列不是大家都会看的成员列表。

同时满足才显示「催催」：

- 被看的人不是自己
- 这个人至少有一项**已经记过、但已经超过建议间隔**的测量

间隔与记录页、达标榜相同：体重和静息心率 1 天，腰围和血压 3 天，臀围和颈围 7 天，身高在 20 岁及以下为 365 天。超过 20 岁且已经记过的身高不算过期，不能因为身高去催。

从没记过的项不算「时效外数据」。七项都还是空白时，不出现催催。

没有任何过期项时，不显示「催催」。图标是否还在，看第 3 节，不看是不是已经全部回到时效内。

---

## 3. 每天一次，图标怎么数

- 同一个催的人，对同一个被催的人，在同一个群、同一个北京时间日期里，只能成功一次。
- 第二次点：按钮变为「今天已催」，不再多一个图标。
- 每一次成功的催促是一个 😜，不用 `+3`。同一个人隔天再催，会再增加一个，直到对方提交新测量。
- 图标留到被催的人在记录页成功保存至少一条新测量。纠正里改旧记录不算。一次保存清掉这个人在所有群里还亮着的催促图标。零点不清空。
- 还没保存新测量之前，图标可以跨天累积。这是 2026-10-20 确认的留存规则。

自己不能催自己。不在这个群的人不能催，也看不见这个群的图标。一个人在两个群里，催促分开计，不串到另一个群。

同一天里，对方补记后又再次过期的情况很少（体重至少要再过一天）。若发生：按钮可以再出现，但今天已经催过的人不能再催第二次。

---

## 4. 图标

表情用 **😜**（2026-10-20 确认），重复排列。不用图标文件，不引入图标字体，和现有的火苗一样嵌在名字旁边。

火苗继续表示连续天数。两者可以同时出现。

读屏时不靠数表情：这一段的替代文字是「有 3 次催促，记下新测量后消失」，视觉上仍是三个表情，没有 `+3`。

按钮本身是文字「催催」，点成功后该按钮当天变为「今天已催」。

## 5. 技术设计（确认后）

新表 `nudges`：

| 列 | 含义 |
|----|------|
| group_id | 哪个群 |
| actor_id | 谁催的 |
| subject_id | 催谁 |
| nudged_on | 北京时间的日期 |

唯一索引：`(group_id, actor_id, subject_id, nudged_on)`。靠这一条保证每天一次，不靠页面上把按钮藏起来。

成员退出或账号删除时，相关催促一并删除。

打开群榜时多一次查询：这个群、今天的全部催促，按被催的人分组。家庭群组规模下这一次查询相对指数计算可以忽略。

卡片现在整行是一个链接。催催是按钮，不能嵌在链接里面。确认后把这一行改成「左侧链接 + 右侧按钮」，点名字或空白处仍进指数，点催催不跳转。

接口：`POST /groups/:public_id/nudges`，参数只有被催的人。成功后回到该群当前榜，状态 303。不是同群、催自己、对方并没有过期项、或今天已经催过，都不新增行。已经催过时回到页面，按钮保持「今天已催」。

不使用队列，不在保存时给其他成员发请求。

迁移文件在确认后写出，由你在本地执行 `docker compose exec web bin/rails db:migrate`。生产在下次部署启动时准备数据库。

## 6. 验收（确认并实施之后）

- [ ] 有过期测量的他人卡片出现「催催」；自己的卡片没有；七项都没记过的人没有
- [ ] 甲催乙一次后，全体成员看到乙的卡片多一个 😜；甲再点不增加
- [ ] 丙再催一次，乙的卡片变成两个 😜，没有 `+2`
- [ ] 过了零点、乙还没新保存测量时，图标仍在；甲可以再催一次，图标再增加
- [ ] 乙在记录页成功保存一条新测量后，图标消失。只在纠正里修改旧记录时，图标还在
- [ ] 乙没有任何过期项之后，按钮消失
- [ ] 另一个群看不到这次催促
- [ ] 连续天数火苗仍在，排序规则不被催促改变

**非目标**

- 第一版就做系统推送（见 §8，可以后做）
- 邮件、未读红点
- 催促本身计入排行榜分数
- 对「从没记过」的空白项催促

## 8. 别人的屏幕能不能马上出现新图标

网页可以做即时推送，但和「缓存显示完再核对」不是同一种能力。

| 方式 | 谁能看见 | 要什么 | 这次怎么定 |
|------|----------|--------|------------|
| 打开页面后的核对 | 正开着群榜或成员列表的人。缓存先出现，指纹不同就用 Turbo Stream 换掉那张成员卡 | 见 `client_cache_v1.md` §5.1。催促成功的这次 POST 不负责去叫其他人的手机 | 和缓存一起做。第一版的「马上」指这个 |
| 系统推送 | 没开着网页的人也能在通知栏看到「有人催了你」 | 服务工作线程、用户点允许、以及向浏览器厂商的推送服务发一条消息。点催促的那个请求里就能发出去，不必另开定时任务 | 第一版不做 |

推送的限制：

- 苹果手机只有在「添加到主屏幕」之后，系统才允许网页推送（iOS 16.4 及以后）。Safari 普通标签页收不到。
- 安卓 Chrome 可以在浏览器里问一次是否允许通知。
- 缓存已经使用这一个服务工作线程。推送如果以后要做，必须写进同一个文件，不能再注册第二个。这一版催催不发推送。
- 生产容器会休眠。推送由「催催」这次请求顺手发出，不依赖容器一直醒着。对方的手机由系统显示通知，不需要我们的服务器保持长连接。
- 现有的 Action Cable 在这套生产配置里是进程内的，容器一休眠就断，不能用来刷新其他成员的页面。

因此：第一版保证「正在看这页的人，核对返回后卡片上多出图标」。口袋里的手机会在下次打开或点刷新时看到。系统推送留到主屏幕和服务工作线程一起做时再开，不在催催的第一版里单独上。
