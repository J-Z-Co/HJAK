## 1. 结论

海外节点会让人与人之间差很多。未备案不是现在这种差别的原因。

Vercel 官方说明：它在中国大陆没有服务器，也没有 CDN 节点。大陆用户的请求要经过国际出口，落到香港、东京、新加坡或其他境外节点。`*.vercel.app` 还可能被部分网络限速或拦截，而且同一天、不同运营商的结果可以不一样。官方不保证大陆访问的速度或可用性。来源：[Accessing Vercel-hosted sites from mainland China](https://vercel.com/kb/guide/accessing-vercel-hosted-sites-from-mainland-china)。

工信部 ICP 备案看的是服务器在不在中国大陆。源站和 CDN 都不在大陆时，不办这项备案。现在这套部署因此不需要、也办不成 Vercel 上的备案。没备案不会单独把页面变慢。只有以后把计算或大陆 CDN 放进大陆，备案才会变成必需手续，而 Vercel 不提供大陆机房。来源：Vercel 上文；阿里云备案说明里「服务器在大陆才要备案，香港和其他境外节点不要」。

所以：慢、偶发打不开、甲快乙慢，先用「人在哪、线路通不通、容器醒没醒」来解释。不要用「还没备案」来解释。

对本仓库，统计用 Vercel 的同域脚本，不安装 React 或 Next.js。具体做法见 §8。数据库已经在新加坡。容器区域已改为新加坡 `sin1`，和库在同一区域。见 §9。

## 2. 为什么同样的网站，不同的人差这么多

差别来自四层。前两层是部署位置，后两层是这套程序自己的行为。四层叠在一起，就会出现「我这边一秒打开，家人那边要等很久，甚至打不开」。

### 2.1 计算在华盛顿，大陆没有边缘节点

Vercel 的计算区域默认是美国东岸的华盛顿（`iad1`）。Hobby 计划只能选一个区域。2026-10-21 从开发环境请求 `https://hjak.vercel.app/icon.png`，响应头 `x-vercel-id` 里出现了 `iad1`。仓库里的 `vercel.json` 现为新加坡 `sin1`。线上在这次部署之前，响应头里仍是当时的区域。部署后应以 `x-vercel-id` 里的 `sin1` 为准。

边缘节点（PoP）和计算区域不是一回事。静态文件可以在离用户较近的节点上缓存。离中国大陆最近的计算区域是香港（`hkg1`），东京、大阪、新加坡、首尔也在亚太。这些都不是大陆节点。来源：[Global network and regions](https://vercel.com/docs/regions)、[Configuring regions](https://vercel.com/docs/functions/configuring-functions/region)。

页面本身是每个人的健康数据，不能放进大家共用的 CDN。所以多数打开仍然要跑到容器所在的那一个区域，再去数据库，再把 HTML 传回来。人在大陆、容器在华盛顿时，这一趟比人在美国东岸长得多。

### 2.2 域名和线路，不是备案

`hjak.vercel.app` 是 Vercel 的子域名。官方写明：大陆的网络控制可以拦截或限速外国域名，包括 `.vercel.app`；没被拦截的流量也要走国际出口。拦截按域名发生，会随时间和运营商变化。今天能开，不保证下周同一条线路还能开。

未备案不等于被拦截。境外主机上的个人站点，大量处于「没备案、有时慢、有时通」的状态。能不能打开，要按具体网址去测，不能从「没有备案号」推出来。GreatFire 一类的探测是按网址记录大陆节点和境外对照的差异，适合做一次核对，不适合当成日常统计。

2026-10-21 已把网站接到自己的域名 `https://hjak.space/`，体感比只用 `hjak.vercel.app` 更好。两个地址同时有效。自有域名降低了 `.vercel.app` 被波及的机会，但不消除跨境延迟，也不能代替备案后的大陆节点。Vercel 明确不建议在部署前面再套一层代理。

### 2.3 容器睡 5 分钟，醒着和睡着是两种网站

生产容器大约 5 分钟没有请求就会休眠，下一次要先醒过来。这是 Vercel 容器的行为，`post_deploy_v1.md` 已经记下。

结果是：刚有人用过的几分钟里，下一个人觉得正常；隔一会儿第一个打开的人要等容器启动，后面紧接着打开的人就快。这和人在不在大陆无关，但会和跨境延迟加在一起。同一个家庭里，谁先打开，谁的感受就更差。

记录页不进 6 小时缓存。保存、登录、注册每次都要叫醒容器。

### 2.4 本机缓存让「第二次」和「第一次」不是同一种体验

生产环境会登记一个服务工作线程。指数、群组列表、群榜、成员指数和近一年，在 6 小时内可以先显示上次的页面。记录页、登录页不缓存。

因此：

- 已经打开过、缓存还在的人，再进群榜会很快
- 第一次打开、换了浏览器、或从主屏幕打开（苹果主屏幕有自己的 cookie 和缓存）的人，仍要等服务器
- 主屏幕上的旧图标、旧页面，也不会因为部署了新代码就立刻换掉

样式和脚本由本站自己提供，带指纹，可以长期缓存。图表用的 D3 在仓库的 `vendor/javascript` 里，不从国外脚本站现拉。唯一的例外是加入群组时扫码用的 `html5-qrcode`，它从 `https://esm.sh/html5-qrcode@2.3.8` 加载。扫码页在大陆比其他页更容易出现「页面开了，扫码却不行」。日常记录和看指数不依赖这个地址。

## 3. 备案在这份部署里处在哪一层

| 问题 | 答案 |
|------|------|
| 现在要不要办 ICP 备案才能解释慢？ | 不要。慢来自跨境和休眠，不来自缺备案号 |
| 继续用 Vercel，办了备案会变快吗？ | 不会。备案号不能在 Vercel 上开通大陆节点 |
| 什么时候才必须备案？ | 把网站或大陆 CDN 放到中国大陆的服务器上时 |
| 香港节点要不要备案？ | 不要。香港也换不来大陆 CDN |
| 公安联网备案 | 那是另一项合规，不是加速手段。本文件不判断该不该办，也不把它写进实现 |

若以后把「家人在大陆必须稳定打开」当成硬要求，才需要大陆主机加备案，并接受维护两套或迁走一套。以目前家庭使用、而且生产站已经能用的情况，不建议为了体验去办备案、迁主机。这是待拍板，不是已经决定。

## 4. 该统计什么，不该统计什么

要回答的是「打开要多久、谁所在的网络更差、是第一次还是缓存、是不是刚把容器叫醒」。不要回答「谁的体重是多少」。

值得留下的只有：

- 页面路径，例如 `/`、`/indices`、`/groups`。不要带测量值、显示名、群组名
- 大致地区、设备、浏览器。到国家或网络这一级就够，不要存可以认出某一个人的标识
- 浏览器感到的等待：首字节时间、页面可交互时间。用来区分「网络慢」和「画完之后才慢」
- 这次打开是服务器新生成的，还是服务工作线程交出来的
- 容器是否刚从休眠起来。这只能在主机日志里看耗时特别长的那一次，不能从页面内容看出来

明确不记：指标数值、血压、出生日期、邮箱、IP 地址进自己的数据库、点击了哪一条健康建议的正文。

## 5. 几种做法怎么比

家庭人数少。统计若会再叫醒容器，或者依赖大陆打不开的第三方脚本，就会把要观察的现象本身弄得更差。

| 做法 | 能看到什么 | 和这套程序的关系 | 建议 |
|------|------------|------------------|------|
| Vercel Web Analytics | 页面、来源、大致地区、系统、浏览器。访客哈希只保留一天，不用 cookie | 脚本在 `/_vercel/insights/script.js`，由 Vercel 在边缘接收，不进 Rails，不叫醒 Puma | 首选。Hobby 每月含 5 万次事件，报表窗口约 1 个月。超出后会停记几天，网站仍运行，不额外扣费 |
| Vercel Speed Insights 免费档 | 一个真实体验综合分，以及按路径的好坏计数 | 脚本在 `/_vercel/speed-insights/script.js`，同样不进 Rails | 可以一起加，但免费档没有按国家拆开的耗时，也没有完整的 LCP / INP / CLS。先不要为此升级 |
| Speed Insights Plus | 各项网页指标，可按国家看 | 要 Pro 计划，约每月 10 美元起，另计事件 | 家庭规模不需要。等免费统计证明「差别主要在某一国的首字节」之后再考虑 |
| 自己的接口收一条耗时 | 能带上「是否来自服务工作线程」这种 Vercel 默认没有的标记 | 每次发送都会打到 Puma。人少也会把休眠中的容器叫醒，样本还会把自己造成的等待算进去 | 现在不做 |
| Google Analytics、百度统计，或另找一台境外统计服务 | 报表更花 | 脚本往往在大陆打不开。官方也建议不要依赖这类第三方。结果是：体验最差的那些人恰恰没被记上，页面还可能被脚本拖住 | 不做 |
| 把日志留在自己的表里 | 想记什么就能记什么 | 多一张表、多一次写入，还容易记下不该记的健康信息 | 不做 |
| 大陆和境外各测一次 `/up` 和首页 | 知道这条网址此刻通不通、首字节差多少 | 不改产品。GreatFire 或两部手机各开一次即可 | 做一次核对，不作为长期工具 |

网页指标发生在浏览器里，接收点在 Vercel 边缘。本仓库的重写原先把所有路径都交给 Rails。§8 已把以 `/_vercel/` 开头的路径排除在外，避免脚本被送进容器后变成 404。部署后仍要在两个域名上打开脚本地址，确认返回的是脚本。

Turbo 换页不会整页刷新。官方脚本会包一层 `history.pushState`，而 Turbo 换页走的就是它，所以仓库里不再额外调用 `pageview`，避免同一页记两次。Speed Insights 量的是整页打开，不量标签切换。上线后应看群榜、指数是否都出现在报表里，而不只是登录后的第一页。若报表里始终只有第一页，再补一次 `turbo:load` 上报。

## 6. 建议的顺序

统计脚本和新加坡容器区域已写入仓库。数据库不迁移。

1. 生产布局已加上 Web Analytics 和 Speed Insights 的同域脚本。免费档的速度分只当作综合分，不拿它做地区结论。你还要在 Vercel 里打开这两个开关，并部署。
2. 用一两周的报表看：打开是否集中在少数路径；大陆和境外的访问量差多少；有没有整段时间没有记录（可能是打不开，也可能只是没人用）。
3. 同一天用大陆一部手机和境外一个网络各请求一次 `/up`。只比较能否连通和首字节，不把响应正文存下来。
4. 数据库留在新加坡，容器区域已写成 `sin1`。不要新建 Neon 项目，也不要导出。部署后看 `x-vercel-id` 是否含 `sin1`。
5. 自己的域名 `hjak.space` 已在 2026-10-21 接上。备案和大陆主机仍留到「必须稳定覆盖大陆」再单独立项。

不在这一步做的：

- 为了统计再叫醒容器
- 记录健康数值或能认出某一个人的标识
- 上 Google、百度或其他要额外加载外国脚本的统计
- 在 Vercel 前面套代理
- 改本地 Docker 的启动方式、日志和端口
- 因为还没备案，就先迁走现在能用的生产站

## 8. 生产统计：不用 React，也不用 Next.js

### 8.1 为什么现有技术栈够用

Vercel 文档里的 React、Next.js 示例，是 `@vercel/analytics` 和 `@vercel/speed-insights` 这两个包装。包装负责在对应框架里插入同一段 HTML。本站是 Rails，页面由 `app/views/layouts/application.html.erb` 输出，没有 React，也没有 Next.js。官方同时提供不依赖框架的脚本地址：

- Web Analytics：`/_vercel/insights/script.js`
- Speed Insights：`/_vercel/speed-insights/script.js`

浏览器加载这两段同域脚本即可。不新增 gem，不新增 npm 包，开发环境和测试环境不加载，避免本地页面去打生产统计。

脚本只在 `Rails.env.production?` 时输出，放在 `head` 里并带 `defer`，不挡住首屏排版。放在 `head` 是为了让 Turbo 换页时沿用已加载的脚本，而不是每次导航都再执行一遍。页面上不设内容安全策略，内联的队列函数可以执行。服务工作线程只拦截页面导航，不拦截这两个脚本。

报表里会看到路径，包括 `/groups/` 后面的群组代号。不发送测量值、血压、姓名、邮箱。加入页查询串里的邀请代号可能随地址出现在 Vercel 的报表里；它不是健康数值，但是入组凭证。这次不自造过滤接口，避免把统计打回 Rails。

### 8.2 仓库里已经改的

1. `app/views/layouts/application.html.erb`：仅生产环境在 `head` 输出两段队列函数和两个 `defer` 脚本。
2. `vercel.json`：重写改为 `/:path((?!_vercel/).*)`，这是 Vercel 文档里「排除某一前缀」的写法。命中的请求仍把原始路径交给容器。`/_vercel/` 不进 Rails。
3. 不额外监听 `turbo:load`。理由见 §5 末段。

### 8.3 要你在 Vercel 上点的

脚本标签本身不会创建接收路由。要先打开功能，下一次部署才会挂上 `/_vercel/insights/*` 和 `/_vercel/speed-insights/*`。

1. 打开项目 `hjak` → Analytics → Enable。
2. 打开 Speed Insights → Enable。若已经开着，就保持。
3. 部署包含本节的提交。两个域名走同一次部署。
4. 部署完成后分别打开：
   - `https://hjak.space/_vercel/insights/script.js`
   - `https://hjak.space/_vercel/speed-insights/script.js`
   - `https://hjak.vercel.app/_vercel/insights/script.js`
   - `https://hjak.vercel.app/_vercel/speed-insights/script.js`
5. 这四个地址都应是 JavaScript，而不是本站的 404 页。然后用浏览器打开首页，在网络面板里应能看到发往 `/_vercel/insights/view` 一类地址的请求。速度数据在离开页面时发送，报表可能要一两天、有若干访客之后才出现。

Hobby 的 Web Analytics 约每月 5 万次事件、报表保留约 1 个月，不用 cookie，访客哈希保留一天，能看大致国家、系统和浏览器。Speed Insights 免费档是综合分和按路径的计数，没有按国家拆开的耗时。

## 9. 容器和数据库放在哪里

### 9.1 已经确认的事实

2026-10-21 晚，生产库 `POSTGRES_HOST` 的主机名中间是 `ap-southeast-1`。这就是新加坡。库已经在 Neon 离中国大陆最近的区域，不需要再新建一个新加坡项目，也不需要导出、导入或更换连接串。

Neon 没有香港，区域在创建时定死，不能把这块库改到香港。Hobby 的容器只能选一个区域。`vercel.json` 已按你的确认写成 `"regions": ["sin1"]`。本地 Docker 的启动方式、日志和端口都不随区域变化：主进程仍是 `bin/dev`。

空闲约 5 分钟后容器仍会休眠。换区域不取消这次冷启动。

### 9.2 这次不要做的

第 4 到第 7 步是「库还在美国或欧洲时，另建新加坡项目再搬数据」。你的库已经是 `ap-southeast-1`，所以：

- 不在 Neon 新建项目
- 不运行 `pg_dump` 或 `pg_restore`
- 不修改 Vercel 里的 `DATABASE_URL`、`POSTGRES_URL`、`POSTGRES_URL_NON_POOLING` 或其他 `POSTGRES_*`
- 不执行 `db:seed`

下面的 §9.4 留作以后库不在新加坡时的操作说明。这次跳过。

### 9.3 建议怎么分

已确认并落实：**容器为新加坡 `sin1`，数据库留在现在这块 `ap-southeast-1`。**

一次打开可以拆成两段往返：

1. 人在大陆，到容器。页面是个人数据，HTML 要从容器所在区域传回来。静态的样式和图标可以落在较近的边缘节点，这段区域设置搬不动它们。
2. 容器到数据库。群组页会按成员读测量、排名和催促，一个家庭通常是几次到十几次往返，而且是一次接一次，不是合并成一次。

大致量级（不是在你的线路上测得的数字，只用来比较）：大陆到香港常常是几十毫秒；大陆到新加坡常常更长，也更看运营商和时段；香港到新加坡大约 30–50 毫秒，这段不走大陆出口；新加坡容器到同区域的 Neon 大约是几毫秒。

因此：

| 分配 | 人到容器 | 容器到库 | 适合现在吗 |
|------|----------|----------|------------|
| 容器华盛顿、库新加坡 | 跨洋 | 跨洋 | 这是区域改动部署前的线上状态。两段都长 |
| 容器香港 `hkg1`、库新加坡 | 大陆出境最短 | 每条查询多大约 30–50 毫秒 | 打开的线路往往更稳，但十几次查询会把省下的出境时间吃回去 |
| 容器新加坡 `sin1`、库新加坡 | 出境比香港长一截 | 同区域，几毫秒 | 已采用。总等待更短，也不搬数据 |

大陆「能不能打开」主要由出境线路和域名决定。香港和新加坡都在境外，换到新加坡不会恢复备案，也不会去掉 5 分钟休眠。`hjak.space` 已经比 `hjak.vercel.app` 更不容易被子域名策略波及。访问质量里剩下、而且这次真能缩短的，是醒着的容器回答页面之前问库的时间。这段只有容器和库同区域才能短下来。

若部署新加坡之后，统计仍显示大陆的等待主要在出境而不是在问库，再把容器改回香港做一次对照。那一次只改 `regions`，仍然不用迁库。

### 9.4 将来才用的迁库步骤

**本次不执行。** 只有将来 `POSTGRES_HOST` 不再是 `ap-southeast-1`、并且你决定把库搬到新加坡时，才按下面做。不要把连接串贴进对话、写进仓库或提交 `hjak.dump`。不要执行 `db:seed`。

本仓库的 `bin/vercel-entrypoint` 在没有 `DATABASE_URL` 时，优先采用 `POSTGRES_URL_NON_POOLING`，其次才是 `POSTGRES_URL`。所以网站实际连哪一台机器，以这两个变量里先生效的那个主机名为准。替换时按变量原来的种类整段替换：原来是池化的，仍填新库的池化串；原来是非池化的，仍填新库的非池化串。

怎么分辨两种串：主机名里带 `-pooler` 的是池化，给运行中的网站连接复用；没有 `-pooler` 的是非池化（Neon 界面里常叫 direct），给导出、导入和 `db:prepare`。密码两边可能不同，不能只改主机名就当成另一条串。

**第 4 步，新建空库**

1. 打开 Neon 控制台，不要在现有项目里找「改区域」。区域不能改。
2. 新建项目。区域选 `aws-ap-southeast-1`（Singapore）。Postgres 版本选 16，和现在的生产库一致。
3. 建好后打开 Connect。分别复制两条串，记在密码管理器或当前终端里：一条带 `-pooler`，一条不带。
4. 新项目此时是空的。先不要到 Vercel 里替换变量。

**第 5 步，从旧库导出，再导入新库**

在 WSL 里安装客户端（没有 `pg_dump` 时才需要）：

```bash
sudo apt-get update && sudo apt-get install -y postgresql-client
```

在 Vercel → 项目 `hjak` → Settings → Environment Variables 里，找到 Production 的 `POSTGRES_URL_NON_POOLING`，用 Show 复制。这是旧库的非池化串。再到 Neon 新项目复制不带 `-pooler` 的串。在终端里只对当前窗口赋值，不要写进任何文件：

```bash
read -rs OLD_UNPOOLED
read -rs NEW_UNPOOLED
```

每行粘贴一条串，回车。`read -rs` 不回显。然后：

```bash
pg_dump "$OLD_UNPOOLED" --no-owner --no-acl --format=custom --file="$HOME/hjak.dump"
pg_restore --no-owner --no-acl --dbname "$NEW_UNPOOLED" "$HOME/hjak.dump"
```

第一行成功时，`$HOME/hjak.dump` 的大小应明显大于 0。第二行可能出现「已忽略」一类提示，因为新库里已有默认对象。出现 `could not connect`、认证失败或中途断开时，停下来，不要做第 6 步。

导入后核对行数，不查询姓名、邮箱或测量值。两条命令的数字应一致：

```bash
psql "$OLD_UNPOOLED" -c "SELECT 'users' AS t, count(*) FROM users UNION ALL SELECT 'measurements', count(*) FROM measurements UNION ALL SELECT 'groups', count(*) FROM groups;"
psql "$NEW_UNPOOLED" -c "SELECT 'users' AS t, count(*) FROM users UNION ALL SELECT 'measurements', count(*) FROM measurements UNION ALL SELECT 'groups', count(*) FROM groups;"
```

数字不一致就保留旧变量，不要切换。用完后从内存清掉两串，并删除导出文件：

```bash
unset OLD_UNPOOLED NEW_UNPOOLED
rm -f "$HOME/hjak.dump"
```

**第 6 步，替换 Vercel 生产环境变量**

只改 Production。Preview 和 Development 若也指向旧主机，一并改成对应环境自己的新串；不要把生产库串填进 Development。

对每一个主机名仍指向旧库的变量点 Edit，整段换成新项目里同一种串，然后 Save：

| 变量 | 填哪一条 |
|------|----------|
| `POSTGRES_URL_NON_POOLING` | 新库、主机名不含 `-pooler` |
| `POSTGRES_URL` | 新库、主机名含 `-pooler` |
| `DATABASE_URL` | 若存在且指向旧主机：与它原来的种类相同。启动脚本看到它非空时，不会再改用上面两个 |
| `POSTGRES_PRISMA_URL`、`POSTGRES_HOST`、`POSTGRES_USER`、`POSTGRES_PASSWORD`、`POSTGRES_DATABASE` | 若存在且指向旧主机，改成新项目 Connect 面板里同名的值 |

只改了变量还不会生效。容器要重新启动才读得到。

**第 7 步，重新部署并核对**

1. 环境变量是在部署当时写进那一次部署的。只对一条旧部署点 Redeploy，有时仍带着那次的旧连接串。变量保存之后，推送一次新提交，或在 Redeploy 对话框里确认使用当前项目设置，让新部署读到新串。部署日志里不应出现连接串。
2. 部署成功后打开 `https://hjak.space/up`，应为 200。再打开 `https://hjak.space/` 和 `https://hjak.vercel.app/`，登录后应仍能看到原来的群组和测量。
3. 若登录失败、页面报数据库错误，或测量不见了：立刻把第 6 步改过的变量改回旧串，再 Redeploy。旧 Neon 项目在确认的这几天里不要删。
4. 连续用过几天、确认新库无误之后，再在 Neon 里删除旧项目。导出文件若还在，删除它。

### 9.5 已经写入仓库的

`vercel.json` 的 `regions` 是 `["sin1"]`，并保留 §8 对 `/_vercel/` 的排除。连接串没有改。

部署后两个域名跟随同一次部署。看响应头 `x-vercel-id` 是否含 `sin1`。若仍是 `iad1` 或 `hkg1`，再到项目设置里把 Function Region 改成 Singapore（`sin1`）。统计脚本要等 §8.3 的开关打开、并且这次部署完成之后才开始记。
